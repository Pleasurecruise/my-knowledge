# Engineering rules

Use concise camelCase domain names; translate foreign naming at adapters. Prefer icons from the shared icon library over hand-written inline SVGs. Validate untrusted input once through its owning schema. Keep transport, application operations, persistence, and presentation separate. Import public module entrypoints across boundaries; prohibit circular dependencies and domain imports of platform code.

Add helpers only for meaningful domain operations, stable contracts, or repeated substantial logic. Do not casually add fallbacks, assertions, unsafe casts, unconstrained types, or hidden mutable state. Expected outcomes use discriminated unions; exceptional failures remain explicit. Permissions, canonical content, secrets, and publication completeness fail closed. Logs must exclude private content, credentials, emails, and search material.

Pin dependencies exactly, retain the 1,440-minute release age, and review lifecycle scripts before changing pnpm build permissions. Keep strict TypeScript and generated platform types. Vite Plus exclusively owns formatting, linting, type checking, and unit tests; dependency upgrades also verify the generated Worker. The lint config registers `@shadcn/lint` as an oxlint JS plugin with `no-restyle` and `no-raw-colors` at error severity. `no-restyle` allows layout classes, grants per-component contracts for the design's intentional exceptions, and is off inside `packages/ui/src/components`, which owns its styling. Brand colors in the identity mark carry documented inline exceptions.

Write documentation in English, 100–200 words per file. Preserve core contracts, use source/tests for exhaustive detail, and rewrite the owning document instead of appending patch sections. Product facts belong in `docs`; temporary plans belong in `.agents`. Preserve user changes, run relevant checks, and obtain Git/deployment authorization separately.
