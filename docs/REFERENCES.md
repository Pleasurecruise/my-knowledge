# References and reuse

[Obsidian](https://help.obsidian.md/) informs portable Markdown, hierarchical tags and explicit links. [my-memos](https://github.com/Pleasurecruise/my-memos) informs chronology, reading/editor interactions and authentication. The owner-local `my-profile`, docu.md and tw93/Kami inform visual composition. These references do not change application routes or storage boundaries.

[Magic UI Tweet Card](https://magicui.design/docs/components/tweet-card) (MIT) informs post composition. Its underlying [react-tweet](https://github.com/vercel/react-tweet) library (MIT) supplies the server API, text entities and media components as a dependency.

Use official [MCP](https://modelcontextprotocol.io/), [OpenNext](https://opennext.js.org/cloudflare), [Cloudflare](https://developers.cloudflare.com/) and [Vite Plus](https://viteplus.dev/) documentation for platform contracts.

Before reuse, inspect licensing, maintenance, compatibility, transitive dependencies, security and replacement cost. Adopt the smallest useful surface and validate the real Worker/browser entrypoint. References are not automatically dependencies; never copy code, skills, fonts, templates or assets without license review. The my-memos reuse has an AGPL-3.0 review; third-party materials need independent checks. The unlicensed markdown-viewer skill remains unbundled.

Browser Run or Sandbox experiments require a concrete benefit, scoped credentials, confirmed account/cost decisions and teardown. They neither replace local verification nor become dependencies merely by appearing in a reference.
